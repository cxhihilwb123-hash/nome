## 2. Classification and evidence vocabulary

- **A — core supported:** an existing `ChatModel` field, controller/API response, or core event is the source of truth. Nome may restyle it without changing semantics.
- **B — existing-state adapter:** the fact exists but Nome needs an Android-only presenter, derived display state, route adapter, or explicit in-flight/error wrapper. The adapter must not manufacture network, security, delivery, expiry, or presence facts.
- **C — currently missing:** the approved design asks for a fact or transition the v6.5.6 client/core cannot prove. It must stay blocked or the product contract must be changed through the GAP decision; no mock, timer fiction, or opportunistic core change.
- **Fixture-only:** deterministic preview/screenshot data is allowed only in Preview/test source sets and can never enter production state paths.

Every implementation row must ultimately contain all of: `zh-CN`, `en`, light, dark, every applicable state, 200% font, 48dp touch targets, TalkBack semantics/order, screenshot comparison, automated test, and a real model/API/core trace. A static screenshot alone never marks a row complete.

### 2.1 2026-07-17 decision freeze

The user delegated the choices to the implementation agent. GAP-08 through GAP-17 use their recorded recommended routes; GAP-18 selects minSdk 28 and makes API 26–27 unsupported. Dark mode is frozen as Nome Dark Token v1 through P02/P07/P17/P21/P23 with unchanged IA, semantics, dimensions, spacing, state set, and accessibility; only surface, contrast, scrim/border, and elevation are remapped.

| GAP | Frozen first-release handling |
|---|---|
| GAP-08 | Indeterminate startup/migration without a true denominator; remove generic restore/rollback/core-timeout claims; distinguish loading/first-use/empty/offline/stopped/unknown. |
| GAP-09 | Fail closed and use configured recovery only; no fabricated lockout countdown before the client backoff contract exists. |
| GAP-10 | Android/client single-submit, typed result, reconciliation, permission Settings recovery, and phase-specific destructive outcomes. |
| GAP-11 | Labelled local scopes and a stable settings index; no recent history or complete global-message claim. |
| GAP-12 | No TTL/expiry/atomic regenerate; local copy/share and core-event peer use/connection remain separate. |
| GAP-13 | No request message; typed reject/address load; withdrawn only from authoritative disappearance; address replace is delete then create. |
| GAP-14 | No verified-admin, direct-report, or Nome-domain claim. |
| GAP-15 | Persistent local identities only; incognito remains per connection. |
| GAP-16 | Progress/cancel/resume/completion only at proven stages; no generic rollback. |
| GAP-17 | Connectivity/configuration/validation/relay/security-event levels remain separate; no aggregate health/E2EE inference. |
| GAP-18 | minSdk 28 decision recorded; no native rebuild/source patch. Phase 1 minSdk 26 and API 26 crash evidence remain unchanged historical facts. |

Decision resolution does **not** change capability classification. Every C row below remains C. `blocked` now means “not a present capability and therefore removed/reworded for the first release or waiting for a later authorized adapter/capability,” not “waiting for a user choice.”
