# Nome iOS v6.5.6 安全迁移计划

## 1. Problem statement

旧版 Nome iOS 成果保存在 iCloud 仓库
`/Users/forkman03/Library/Mobile Documents/com~apple~CloudDocs/Documents/SimpleX`，
代码检查点为 `ca41ed118d12ba2af5913ec848945067cbcbaffb`，交接检查点为
`24337a6205ca72ff6d02ba43a0f5459ad5ea6b04`。当前 Nome Android RC 位于
`6a01efa5e6d10dc0743cdf82dfb69e09cc459862`，必须保留其分支、工作树和证据，
同时避免继续在 iCloud 同步目录中开发 Git 仓库。

迁移必须保留官方 `v6.5.6` / `59fce95d3` 基线，不覆盖 Android、共享 Kotlin、
Haskell/native core、协议、数据库或消息状态机，也不得向任何远端推送。

## 2. Solution summary

在独立工作树 `/Users/forkman03/project/nome/simplex-chat-ios` 和分支
`codex/nome-ios-v656` 中，以当前 Android RC HEAD 为起点，按旧提交的精确增量
选择性恢复 iOS 源码、iOS 工具、设计证据和 iOS 计划/交接文档。iCloud 原目录
保持只读。迁移后新增当前基线的迁移记录，并完成差异审计、脚本测试、Xcode
工程发现和可行的模拟器/通用设备构建验证。

## 3. Detailed technical design

### 3.1 Provenance and compatibility gates

- 当前 HEAD：`6a01efa5e6d10dc0743cdf82dfb69e09cc459862`。
- 官方基线：`59fce95d3cd08897b4ef742447b785cf2e56c7ce` / `v6.5.6`。
- 旧 iOS 父提交：`d492606f01a24c242beef2249c5e3ca5b6f83650`。
- 旧 iOS 代码提交：`ca41ed118d12ba2af5913ec848945067cbcbaffb`。
- 旧 iOS 文档提交：`24337a6205ca72ff6d02ba43a0f5459ad5ea6b04`。
- `HEAD:apps/ios`、`v6.5.6:apps/ios` 和 `d492606f:apps/ios` 的树哈希均为
  `f36c9a4d3f7c2bb7bb8948eab63b0a23042710eb`。
- `HEAD:scripts/ios` 与 `d492606f:scripts/ios` 的树哈希均为
  `9a91e1ead885d5c569311a33d2f2e5878e97edb0`。
- 旧代码提交完整路径清单的排序 SHA-256 为
  `4cb2a0e79eda1ceabe797bc1c29cdd2a9974247884064e5a2744b1f654548b61`。

这些相同树哈希是允许精确恢复 `apps/ios` 与 `scripts/ios` 增量的硬门禁。

### 3.2 Included scope

- `apps/ios/**`：旧提交中的 115 个变更路径。
- `scripts/ios/**`：旧提交中的 69 个变更路径。
- `design/**`：旧提交新增的 Nome 品牌、页面和 App Store 证据。
- 旧提交中的 10 份 iOS 计划，以及 `24337a62` 中的两份进度/交接文档。
- 为本次迁移新增的计划、迁移记录以及产品/规格一致性说明。

### 3.3 Explicit exclusions

- `.gitignore`、根 `README.md` 和 `docs/lang/zh-Hans/README.md` 的旧改动。
- `apps/multiplatform/**` 的 Android 图标、共享图片和共享字符串改动。
- Haskell/native core、`Core.kt`、协议、数据库和消息状态机。
- Bundle ID、App Group、钥匙串组、签名、描述文件和发布域名迁移。
- 任何提交、推送、签名、发布或删除 iCloud 原目录的操作。

### 3.4 Documentation coherence

迁移属于既有用户界面的恢复，不改变 SimpleX 核心语义。新增 Nome iOS 产品覆盖
说明和技术覆盖说明，并在 `product/concepts.md`、`spec/impact.md`、规格索引和
`CODE.md` Document Map 中建立交叉引用。旧计划中的历史 PASS/BLOCKED 只能作为
历史证据；本次必须重新验证后才能声明为当前结果。

### 3.5 Threat model

- **iCloud 同步或占位文件损坏源仓库：** 只从已验证 Git 对象读取，原目录不写入。
- **旧补丁覆盖 Android RC：** 仅在独立工作树恢复白名单路径，并检查越界路径为零。
- **预览 core 被误报为真实通信：** 模拟器预览与真实 core/真机证据明确分离。
- **签名标识破坏现有数据访问：** 本批不修改 Bundle ID、App Group 或钥匙串组。
- **秘密进入仓库：** 审计私钥、证书、描述文件、服务器 URI、邀请链接和常见密钥模式。
- **误推官方仓库：** 本批不提交、不推送；`origin` 继续视为只读上游。

## 4. Detailed implementation steps

1. 建立独立工作树和分支，记录 HEAD、工作树清洁度和源提交对象。
2. 保存旧提交的白名单路径清单与 SHA-256，不修改 iCloud 原目录。
3. 从 `ca41ed11` 恢复 `apps/ios`、`scripts/ios`、`design` 和 10 份 iOS 计划；
   从 `24337a62` 恢复两份进度/交接文档。
4. 检查所有改动均在白名单内，确认 Android、共享 Kotlin、core/协议/数据库越界为零。
5. 补齐 product/spec/source 三层迁移说明、索引和影响图。
6. 运行 shell 脚本语法/单元测试、品牌/设计/计划审计与 Git whitespace/secret 检查。
7. 使用 XcodeBuildMCP 先核对 session defaults，再发现工程、scheme 和模拟器；
   在环境允许时执行模拟器构建/启动并验证 UI，随后执行无签名通用设备构建检查。
8. 生成当前迁移检查点、验证结果和下一线程交接；连续两轮一致性复核均为零问题后结束。
