## Hosted channel-link and relay repair follow-up

- The production failure was isolated to public port 443 ownership, not to the
  channel relay process: XFTP owned 443 directly, so the hosted channel URL
  `https://smp.nome.im/c#...` could not complete normal HTTPS/TLS handling.
- The production host was backed up under
  `/opt/nome/backups/ios-channel-fix-20260730T1505Z` before the repair.
- Nginx now owns public 443 and performs TLS SNI routing. Requests for
  `smp.nome.im` reach the local HTTPS/AASA service on `127.0.0.1:8443`; the
  default/no-SNI path reaches XFTP on `127.0.0.1:24443`. SMP transport remains
  on TCP 5223; it was not migrated to 443.
- Post-repair live checks passed: Nginx configuration, HTTPS `/c/`, AASA JSON,
  the public XFTP TLS path, certificate renewal dry-run, and active
  `nginx`/`nome-chat-relay` services. The `smp.nome.im` certificate expires on
  2026-10-28 and has a deploy hook that reloads Nginx after renewal.
- iOS now recognizes hosted `/c` links, keeps their resolver host when handing
  them to Core, and declares both production and developer-mode associated
  domains for `smp.nome.im`. Nome relay address rotation additionally requires
  the `Nome Relay` name plus a `nome.im` domain/host, preventing an unrelated
  same-named custom relay from being rewritten while preserving user
  `enabled`/`deleted` choices.
- Simulator B opened A's hosted channel link, showed a verified link signature,
  joined through `Nome Relay`, received history, and remained a read-only
  subscriber. A sent two fresh broadcasts; B received them in exact order.
- A then broadcast the repository's public Nome icon. B received the real image
  and opened it full-screen. The 443 stream log recorded the corresponding
  no-SNI XFTP byte transfer, proving the default XFTP route rather than only a
  UI placeholder or server object.
- Both simulators were terminated and relaunched. The channel subscription,
  ordered messages, image, owner broadcast composer, and subscriber read-only
  composer persisted. After the final source review change, Nome `6.5.6 (349)`
  was rebuilt, installed over both apps without uninstalling them, and the same
  state/open-image checks passed again.
- This follow-up reused the existing simulator Core and did not rebuild Core.
  It did not alter the separate build 378 physical-device Core result above.
