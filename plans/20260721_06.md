# Nome iOS offline-device readiness parser fix

Date: 2026-07-21
Status: complete

## 1. Problem statement

`scripts/ios/check-ios-device-readiness.sh` parses `xctrace list devices` from
`== Devices ==` until `== Simulators ==`. Current Xcode output inserts a
`== Devices Offline ==` section between those headers, so an offline iPhone and
even the offline-section header are reported as connected. This can advance a
physical-device gate on false evidence.

## 2. Solution summary

Extract the existing awk logic into a small stdin parser function inside the
same script, stop the connected-device section at every subsequent `== ... ==`
header, and expose a read-only `--parse-xctrace-devices` mode for deterministic
fixture tests. Add a focused shell test with connected, offline-only, and mixed
fixtures. Update architecture/testing guidance and the product gap register.

## 3. Detailed technical design

The parser owns only classification of raw `xctrace` sections. It starts after
the exact `== Devices ==` header, stops at the next section header, ignores
blank lines and the local Mac host's standard UUID-shaped identifier, and
prints remaining physical device rows unchanged. It does not classify by
user-controlled device names. The normal readiness command passes live
`xctrace` output through the same function used by the fixture test.

No device state, Core library, Xcode project, identifier, simulator, or Android
file is mutated.

### Threat model

An offline, stale, or attacker-controlled device name must not be able to make
the release evidence claim a live physical target. Section boundaries are
therefore authoritative; content under `Devices Offline` is never considered
connected. Device names are treated as opaque output and are not evaluated as
shell code. The parser emits text only.

## 4. Detailed implementation steps

1. Add `parse_xctrace_devices` and the fixture mode to
   `scripts/ios/check-ios-device-readiness.sh`.
2. Replace the duplicated inline awk pipeline with the function.
3. Add `scripts/ios/test-check-ios-device-readiness.sh` covering:
   connected device only, offline-only device, mixed connected/offline output,
   and a device name containing spaces.
4. Document the corrected evidence boundary in
   `apps/ios/spec/architecture.md` and resolve the discovered item in
   `apps/ios/product/gaps.md`.
5. Run the focused test, related readiness export test, shell syntax checks,
   `git diff --check`, and the live read-only readiness command.

## 5. Testable acceptance criteria

- Offline-only fixture produces no connected device rows.
- Mixed fixture produces only rows from `== Devices ==`.
- Mac host rows are excluded by identifier shape and physical device rows,
  including names containing Mac model words, are preserved verbatim.
- The normal script reports the currently offline `CryHandsome` device as
  `BLOCKED`, not connected.
- Existing readiness export tests still pass.
- No iOS build, Core preparation, Android mutation, or remote push occurs.
