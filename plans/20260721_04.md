# Nome iOS 深色模式可读性收口计划

## 1. Problem statement

迁移后的 14 状态浅色模式烟测已经通过，但 2026-07-21 首次完整深色模式烟测显示，Nome 多个页面仍把固定品牌深蓝 `#0E1B2D` 直接用于正文和标题前景色。该颜色在黑色或深灰背景上的对比度明显不足，影响引导、首页、添加朋友、加入群组、会话详情、身份中心、公开联系方式和设置页面的可读性。

这不是通信核心问题，也不需要重做布局；需要把“用于文字和图标的品牌深蓝”与“用于品牌色块的固定深蓝”分离，并保留现有浅色外观。

## 2. Solution summary

- 各 Nome 局部 palette 的 `navy` 改为随 `UITraitCollection` 解析的前景色：浅色模式继续使用 `#0E1B2D`，深色模式使用系统 `label` 颜色。
- 需要白色前景的深蓝色块继续使用新增的固定 `brandNavy`，避免深色模式下出现浅色底加白色图标。
- 不修改布局、交互、状态、API、数据库、协议、Haskell/native core、Bundle ID、App Group 或签名设置。
- 更新 product/spec 文档，记录深色前景色必须自适应的产品和技术约束。

## 3. Detailed technical design

### 3.1 Affected presentation modules

- `Shared/Views/Onboarding/`
- `Shared/Views/ChatList/ChatListView.swift`
- `Shared/Views/NewChat/`
- `Shared/Views/Chat/ChatView.swift`
- `Shared/Views/UserSettings/`

这些文件都属于 `PC32 Nome Product Experience` 的现有影响范围；不新增路由、状态或数据流。

### 3.2 Color behavior

`navy` 只代表可读的 Nome 前景墨色：

- Light：固定品牌深蓝 `#0E1B2D`。
- Dark：`UIColor.label.resolvedColor(with:)`，继承系统深色与增强对比度语义。

`brandNavy` 始终保持 `#0E1B2D`，仅用于配有白色前景的品牌色块。绿色、蓝色和紫色功能强调色不在本批改变。

### 3.3 Threat model

- **低对比度隐藏安全说明或危险操作：** 所有 Nome 深蓝前景统一改为深色自适应，不仅修标题，也覆盖图标和说明。
- **把自适应文字色误用于白色图标背景：** 深蓝填充明确改用固定 `brandNavy`。
- **主题修复改变业务或通信语义：** 只修改 SwiftUI 颜色常量和文档，不触碰任何状态、API 或核心路径。
- **预览截图被误报为真实通信：** 深色烟测仍只证明 UI；真实 core、真机和双账号门禁继续保持阻塞。

## 4. Detailed implementation steps

1. 保存本地迁移检查点 `3edd26fcd`，确认未推送远端。
2. 运行完整深色模式 14 状态烟测，保存修复前证据和哈希。
3. 修改局部 Nome palette，并把配有白色前景的固定深蓝填充切换到 `brandNavy`。
4. 更新 `product/views/nome-experience.md`、`product/gaps.md`、`spec/client/nome-brand-overlay.md` 与相关源码行号引用。
5. 运行 Swift 编译、26 个脚本测试、品牌/设计检查、浅色与深色 14 状态烟测及视觉质量检查。
6. 逐张审阅深色 contact sheet，确认关键标题、说明、图标和按钮可读。
7. 连续执行两轮 product/spec/source 一致性与 Git diff 审查；两轮均为零问题后做本地提交，不推送。
