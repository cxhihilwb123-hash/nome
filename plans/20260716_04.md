## 7. API 26 minimum-version result

The API 26 system image and dedicated AVD were installed and booted successfully. The arm64 debug APK installed, but cold launch failed:

```text
java.lang.UnsatisfiedLinkError: dlopen failed: cannot locate symbol "getentropy"
referenced by .../lib/arm64-v8a/libsimplex.so
```

To isolate the cause, the official signed v6.5.6 `simplex-aarch64.apk` was installed on the same AVD. It reproduced the identical error from its own `lib/arm64/libsimplex.so`. NDK 23.1.7779620 `sys/random.h` marks `getentropy` as `__INTRODUCED_IN(28)`. `llvm-readelf --symbols` confirms the unresolved reference in both official arm64-v8a and armeabi-v7a `libsimplex.so`; armv7 is therefore not claimed as a workaround.

Raw evidence is preserved as `api26-official-v656-crash-logcat.txt`, `api26-local-debug-start.txt`, `api26-local-debug-crash-logcat.txt`, `api26-device-getprop.txt`, `getentropy-*.txt`, and `ndk23-getentropy-api-level.txt`.

Classification: official native artifact / declared-minimum compatibility failure, not a Nome UI failure and not a local wrapper-build failure. No native source was changed. The decision is recorded as GAP-18: produce exact-commit API 26-compatible native artifacts without source changes, or truthfully raise Nome minSdk to 28.
