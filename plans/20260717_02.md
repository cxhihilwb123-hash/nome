## 1. Problem

本计划启动时，Phase 0/1、264 行状态矩阵、API 35 真实 core、48/48 证据和官方
双语明暗 baseline 已完成，但生产 Nome UI 尚未开始。当时 Phase 2 之前仍有三类门禁：

1. GAP-08～18 原先仍标记为未决，导致实现线程无法区分“能力缺失”与
   “产品已决定删除/改写”；
2. 官方 v6.5.6 声明 minSdk 26，但两个 ABI 的 native artifact 均引用 API 28 才提供的
   `getentropy`，API 26 实机路径已证实启动崩溃；
3. 已批准 PNG 只冻结明亮方向，dark tokens 与 Android-only source placement 尚未形成
   可执行约束。

若不先冻结这些事实，Phase 2 容易把 mock 当 core truth、把 C 行误升为能力、把官方
dark baseline 误称 Nome dark approval，或让 Android 视觉外壳扩散进 `commonMain` 和
Desktop。

## 2. Solution

本计划冻结以下结论：

- GAP-08～17 全部采用 `product/gaps.md` 的推荐路线，并用本文第 3 节的精确语义消除
  歧义；
- GAP-18 选择 **Nome minSdk 28**，API 26–27 明确 unsupported；不做 native rebuild，
  不改 Haskell/native source；
- 暗色采用 **Nome Dark Token v1**，代表页固定为 P02、P07、P17、P21、P23；保持与
  已批准明亮稿完全相同的 IA、语义、组件尺寸、48dp 目标和状态集合，只允许 remap
  surface、contrast 与 elevation；
- Phase 2 生产基础仅进入 Android-controlled source sets；`commonMain`、Desktop、iOS、
  core、数据库/协议/消息状态机均不进入本批次；
- 现有矩阵中的 C 行继续是“当前能力不存在”。决策只决定首版删除、改写或等待
  Android/client adapter，绝不把 C 改成 A/B 或 `implemented`。

## 3. 冻结的产品决策

### GAP-08 — Startup and empty-state truth

- 保留官方根状态优先级和真实分支。
- 无真实 numerator/denominator 或 stage 时仅使用 indeterminate progress。
- 删除 staged percentage、广义 restore/rollback 和 core timeout 保证。
- 客户端等待阈值只能提供 diagnostics/retry，不得宣称 core failure。
- P08 明确区分 loading、first-use、true empty、filtered-empty、device-offline 与
  core-stopped；未收到真实网络 callback/ack 时显示 unknown。

### GAP-09 — Local-auth fail-safe

- 用户启用锁后 fail closed；`Unavailable` 不得授权或自动关闭保护。
- 只允许进入已配置的 device credential / app passcode 恢复路径。
- app-passcode backoff 属于 Android/client state，与 self-destruct 完全隔离。
- 在 `spec/state.md` 后续冻结阈值、时钟和跨重启策略前，不显示虚构 lockout 倒计时；
  P02 dark representative 使用 unavailable/recovery 状态。

### GAP-10 — Async operation and permission state

- 既有 API 外增加 Android/client operation state：single-submit、真实 typed result、
  model reconciliation、失败保留与安全 retry。
- 永久权限拒绝提供 Android Settings route，并在 resume 后重新读取平台事实。
- 跨越 destructive boundary 后必须保留阶段/部分失败，不得以本地布尔值清 UI 或宣称
  成功。

### GAP-11 — Search

- P09 使用明确分 scope 的 coordinator；联系人、群组、频道来自已加载 local chat
  truth。
- 首版不宣称完整 global message aggregation；不支持的 grouped-messages C 状态删除或
  改写为受限单会话 scope。
- P23 使用 allowlisted stable route-id 的本地 settings index。
- 首版不保存 recent query，不写偏好或日志。

### GAP-12 — Invitation lifecycle

- 删除 TTL、倒计时与 expired 状态。
- generated、copied、shared、waiting、peer-use-observed、connected 分开表示。
- copied/shared 仅是本机动作；remote use/connection 只能由真实 core event 推进。
- 首版不提供“原子重新生成”；若创建新邀请，必须称“创建新邀请”，且在真实 invalidation
  成功前旧链接仍按可能有效处理。

### GAP-13 — Request and address lifecycle

- P14 删除 optional request message。
- Reject 使用 discriminated client result；只有 typed reject response 才移除请求，错误时
  保留。
- withdrawn 只由 authoritative disappearance/not-found 表示为“请求已不可用”，不编造
  原因。
- P15 的裸 `userAddress == null` 是 unknown/loading；只有 typed not-found 才是 off。
- replace 拆成 delete 与 create 两个确认阶段，各自呈现结果；不承诺 atomicity/rollback。

### GAP-14 — Group/report/channel claims

- 删除 verified-admin-contact；link/owner verification 不等同联系人安全码验证。
- 删除 direct-chat report；仅在现有 group-message eligibility gate 下调用真实 group
  report route。
- 首版只输出官方兼容 link；不生成 Nome slug/domain。

### GAP-15 — Anonymous identity semantics

- 持久项只叫 local identity / 本地身份。
- incognito 只解释为“本次连接使用独立隐身身份”；不创建持久列表行、可复用 ID 或
  anonymous account。

### GAP-16 — Archive and migration recovery

- 只有真实 byte event 可以 determinate；其余阶段 indeterminate。
- cancel 仅在真实 API/file handle 支持的阶段开放；irreversible boundary 后禁用。
- resume 只描述已证明的 persisted checkpoint；receiver incomplete download 重新开始，
  sender process death 不支持 resume。
- 只建议迁移前备份，不承诺 rollback。
- 后续高风险页面批次必须修正 secret `rememberSaveable`、提前 `YesUp`、
  `InvalidConfirmation` 误判、corrupt checkpoint crash 和未验证终态清 checkpoint 等
  client 问题；这些不进入当前 foundation 批次。

### GAP-17 — Network evidence levels

- 分开 device connectivity、configuration、single validation、operator/server、per-group
  relay 与 item-level security event。
- 默认/不可用 sentinel 显示 unknown。
- 禁止汇总成 private routing healthy、global network/relay healthy 或 persistent aggregate
  E2EE。
- P21 的 public-channel non-E2EE disclosure 固定来自 channel mode；
  `E2EEInfo.public` 只渲染对应事件项。

### GAP-18 — Minimum SDK

- Nome release minimum 冻结为 **API 28**；API 26–27 unsupported。
- 不做 exact-commit native rebuild，不改 native/Haskell source。
- Phase 1 的 `minSdk 26` 构建记录与 API 26 crash evidence 是历史事实，原文和证据均不
  改写。
- Android app/common Gradle、debug/release merged manifest 和 arm64 debug APK badging
  均已验证为 28；clean API 28 与 API 35 same-package non-empty upgrade 均启动真实
  server/receiver。API 35 immediate checkpoint 的 chat database/preferences 保持
  byte-identical；agent database 是运行时可变文件，不宣称字节不变。

## 4. Nome Dark Token v1

### 4.1 代表页

P02、P07、P17、P21、P23 是 dark v1 的唯一冻结代表集，分别覆盖：

- local-auth/secret entry；
- populated list/navigation；
- direct message/content hierarchy；
- public-channel disclosure/relay state；
- settings/forms/status summaries。

### 4.2 不变量

- IA、route、copy semantics、information priority 与 light baseline 相同；
- component geometry、spacing、radius、type scale、icon size、48dp target 与 safe-area
  规则相同；
- state set 与 evidence classification 相同，不能因 dark mode 增删状态；
- public-channel disclosure、danger、error、focus、disabled、unread 与 delivery 不得只靠
  颜色区分；
- 200% font、TalkBack traversal、focus restoration 与 predictive back 契约不变。

### 4.3 允许的重映射

Dark Token v1 只允许：

1. background/surface/container/scrim 的暗色 surface mapping；
2. text/icon/divider/status 的 WCAG contrast mapping；
3. 用 surface tier、border 与受控 overlay 表达 elevation，不能改布局或添加装饰层级。

代表页原生截图、contrast report、asset SHA-256 和 light-reference overlay 已进入
`plans/evidence/20260717_nome_android_phase2_foundation/`。这只验证 foundation 的
Dark Token v1；其余 production 页面仍须按页重复视觉、真实状态和无障碍验证。

## 5. Android-only source placement

以下 placement 已在任何 source edit 前冻结，并由本 foundation 按原路径实现：

| Responsibility | Allowed source placement | Rule |
|---|---|---|
| Nome tokens/theme/components/accessibility | `apps/multiplatform/common/src/androidMain/kotlin/chat/simplex/common/ui/nome/{tokens,theme,components,accessibility}/` | Android-only foundation；不得新增 presenter、协议或 model truth |
| Activity/system insets/back/permission/intent host | `apps/multiplatform/android/src/main/java/chat/simplex/app/nome/` | future/reserved；本批未添加 production host source |
| deterministic fixtures, screenshot harness, Preview entry | `apps/multiplatform/android/src/debug/java/chat/simplex/app/nome/` | debug-only；不得进入 production state path |
| JVM/unit tests | `apps/multiplatform/android/src/test/java/chat/simplex/app/nome/` | tokens/components/accessibility/state exclusivity |
| instrumentation/device tests | `apps/multiplatform/android/src/androidTest/java/chat/simplex/app/nome/` | semantics、permission、intent、lifecycle、真实 core/device |

冻结规则：

- 本批次不向 `commonMain` 添加 Nome shell/theme/component；
- 现有共享 `ChatModel`、controller/API 只消费，不 fork，不创建第二状态源；
- 若后续 typed result 无法在 Android adapter 保真，必须另开范围说明共享理由，并运行
  `desktopTest` 与 Desktop 视觉/行为回归；不得绕过 wrapper 直连 native；
- Preview/test fixture 只能从 debug/test source set 注入，release/production build 必须无法
  引用。

## 6. Technical design

Phase 2 foundation 的依赖方向固定为：

```text
android main host
        |
androidMain Nome tokens/theme/components/accessibility
        |
existing Compose routes and Android platform adapters
        |
existing ChatModel + ChatController + AppPreferences
        |
unchanged official v6.5.6 JNI/native core + local database
```

首批只允许：semantic tokens、theme adapter、surface/app-bar/card/field/banner/progress/error
等基础组件、accessibility primitives、Preview/debug fixture、screenshot harness 和必要 host
glue。本 foundation 不新增 presenter；后续 Android adapter 的输入仍必须是 `CoreBacked`、
`Derived`、`ClientOperation` 或显式 `Unavailable`。C 能力不得由 fixture、timer、静态 badge
或 optimistic default 注入生产路径。
