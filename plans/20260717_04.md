## 2. Why the batch is split before source

The reserved app-module production path can own the Android Activity/window contract, but it
cannot faithfully replace the actual home route:

1. `MainActivity` delegates to shared `AppScreen`.
2. `AppScreen` owns the root gates, `SimpleXTheme`, calls, auth, overlays, onboarding, and
   safe-area behavior.
3. `AndroidScreen` owns the official `chatId` list/chat navigation.
4. `StartPartOfScreen` directly selects delivery receipts, share intent, or `ChatListView`.
5. P07/P08 list/loading/filter state is private to the shared chat-list implementation.

An Activity overlay or a second root would fork navigation and risk hiding auth/call/share
states. Therefore this plan freezes two consecutive implementation stages before any
production source is written.

### Batch 2A — production shell contract

- Add the minimal app-module host under
  `android/src/main/java/chat/simplex/app/nome/`.
- Keep `enableEdgeToEdge`, intent processing, auth/back dispatch, calls, and root gates owned by
  the existing Activity/shared root.
- Add one narrow shared platform home-route wrapper. The Android and Desktop actuals initially
  delegate the unchanged official chat list.
- The shared declaration contains no Nome UI or state derivation.
- The Desktop actual must remain an exact fallback and must pass `desktopTest` plus a recorded
  visual/behavior regression.

### Batch 2B — P07/P08 home truth adapter

- Add the Android actual renderer and adapter under
  `common/src/androidMain/kotlin/chat/simplex/common/ui/nome/home/`.
- Preserve `ChatModel`, the receiver, the existing `CC.ApiGetChats` / `CR.ApiChats` controller
  path, event ordering, and official navigation as the only data/control sources; typed
  `apiGetChatsResult` is the authoritative Kotlin caller surface.
- Add only the smallest shared, typed chat-list load provenance needed to distinguish a
  same-user/same-host successful empty result from an unavailable result. It wraps the existing
  command; it does not add `sendCmd`, a protocol command, or a second API/model.
- Expose Android platform-connectivity first observation from the existing `NetworkObserver`.
  Before that observation, connectivity is unknown even if the legacy model sentinel is
  `OTHER/online=true`.
- Bind rendered rows to the user/host generation that produced the loaded result. A changing
  identity must suppress stale rows.

## 4. Truth model

The adapter has independent content, connectivity, and core axes. Offline or stopped can coexist
with cached rows; neither means the list is empty.

### Content axis

| State | Required facts | Forbidden shortcut |
|---|---|---|
| Loading | root chat state unknown; user/host switching or generation mismatch; or an in-flight load that explicitly hides rows or has no cached base rows | `chats.isEmpty()` alone |
| First use | root explicitly reports no local/current user | empty list alone |
| True empty | typed `ApiChats` success for the current user/host generation and zero chats | no-user/API failure |
| Filtered no result | typed loaded base list is non-empty, an existing active filter is set, and the existing filter produces zero rows | clearing/mutating the base list |
| Populated | typed loaded rows for the current generation, including a non-hiding same-generation refresh with cached visible rows | fixture/timer |
| Unavailable | same-generation typed load failure | showing true empty |

Source reachability review found two narrower facts after this table was frozen:

- `FIRST_USE` remains a truthful adapter/renderer result for explicit no-user input, but the
  unchanged production root routes that fact to onboarding before `PlatformHomeRoute`; it is not
  currently reachable on the production Nome home.
- `FILTERED_NO_RESULT` remains a truthful adapter/renderer result for an already-active filter,
  but this batch excludes tag/filter controls and a fresh Android home has no producer for a
  non-null active filter; it is not currently reachable through the bounded production UI.

These two renderer branches and their deterministic tests are defensive contracts, not
real-core/production-route evidence. Their required P08 production gates remain blocked. Expanding
root onboarding or adding a filter interaction would be a new scope decision and is not inferred
by this batch.

### Connectivity axis

- `Unknown`: `NetworkObserver` has not produced a platform observation.
- `Online`: the observed active network is validated.
- `DeviceOffline`: the platform observation says no validated device network.

These states never claim relay, server, global service, or message-delivery health.

### Core axis

- `Starting`: `chatRunning == null`.
- `Running`: `chatRunning == true`.
- `Stopped`: `chatRunning == false`.

Stopped keeps any same-generation cached rows read-only and disables actions that would require
the core.

## 5. Included production behavior

- P07 same-route populated chat projection in core order.
- Read-only name, summary, timestamp, favorite, and unread semantics from existing chat facts.
- Official navigation helper only for already-ready conversations; no replacement nav stack.
- Read-only connection/request rows without accept/reject/connect mutation.
- P08 production-reachable source paths for skeleton loading, true empty, network unknown,
  device offline, core stopped, and explicit unavailable load.
- Defensive renderer/adapter branches for first use and filtered no result; they are not claimed
  as current production-route behavior for the reachability reasons in §4.
- Existing Nome theme, dimensions, surfaces, state panels, and accessibility primitives.
- zh-CN/en, light/dark, 100%/200%, 48dp, and TalkBack-facing semantics.
